The two controls now produce DIFFERENT rows and DIFFERENT remediations:
  A (container wedged)  -> "N Pod(s) scheduled but 0 ready — a CONTAINER is stuck,
                            not the scheduler" + names the container and its reason,
                            and warns the plugin may already be installed.
  B (nothing scheduled) -> "present but NO Pods scheduled while N GPU node(s) exist"
                            + the nodeSelector/taint guidance (correct HERE, and only here).
Before the fix BOTH printed B's message. On this cluster the true fault was A, so the
checker sent us to inspect labels while a 404ing sidecar image was the actual cause —
the DaemonSet had been not-Ready for 2d22h.

Both faults were reverted after capture; the cluster ends 2/2 Ready, pass=6 fail=0.
