# DIAGNOSIS: 'ncclRemoteError / remote process exiting prematurely' on the SURVIVING
# ranks almost always means ANOTHER rank died (OOM-killed, node preemption, segfault,
# or here a manual pod delete) — not a fault in the rank printing the error. The first
# rank to CRASH is the root cause; the others just report the broken connection. Triage
# by finding the rank that exited FIRST / has a non-NCCL error, and check for OOMKilled
# pods, node NotReady, or XID errors on that rank's GPU. Contrast a true HANG (peer alive
# but stuck), which instead waits the full timeout and prints 'Watchdog caught collective
# operation timeout ... Timeout(ms)=60000'.
